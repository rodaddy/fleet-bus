Purpose

The fleet is one NATS substrate with many clients — Hermes agents, rtech-agents, you-local, Open Brain, k-board, Dash. They were meant to move forward together, bus-first, with agents as the first validator. Instead each package grew its own truth: three fleet packages that all touch the wire drift from each other; the message shapes are frozen dataclasses described by docstrings rather than an enforced spec; coordination signals ride prose trailers ([[done]], [[stance:]]) an agent must remember to emit; and durability is off everywhere (at-most-once) while the docs claim guarantees the transport does not provide.

The fix is a single base package every client imports: packages/fleet-core. The spec is code — import fleet-core and you are a compliant citizen.

The spine

Non-negotiable fleet-core owns the message spec (Pydantic), config, logging, and a default transport. Every fleet package and downstream app depends on it. If a client imports only fleet-core it is correct on the bus: connected the standard way, logging the standard way, emitting standard-shaped validated messages. Everything above (orchestration, subscriber adapters, agent engines) is opt-in capability, never a prerequisite for being on the bus properly.

  • Spec = Pydantic, not prose, not dataclasses. Envelope, heartbeat/presence, stance, done, and the typed act/state enum are Pydantic models. Static-ish: agreed fields validate hard; ConfigDict(extra="allow") lets a client carry its own signal (an agent's active_turn, a worker's role/lanes) without forking the class or breaking a reader that does not know the field. Honors the closed C2 policy (#111): unknown-field preservation, additive-only within a major, explicit versioning.
  • Durable-by-default. JetStream on for almost everything; core-NATS is the declared opt-out. The asymmetry decides it — on-when-unneeded is harmless, off-when-needed is silent loss.
  • Transport has a blessed default, one override seam. Import fleet-core, get a correct transport. Exotic needs override that one method in a subclass; the spec + subjects are load-bearing invariants, not override-able.
  • uv-git-installable. Downstream apps uv add fleet-core from a private GitHub ref; versioning kept correct so pins resolve across clients on different cadences.

Durable-by-default — and the one exception

JetStream is on by default. On-when-unneeded costs a little overhead and some stream state nobody reads; off-when-needed is a task frame that vanishes with no error. Those are not comparable failures, so the base biases to the harmless one. Durability is what a new client inherits for free; losing it is an explicit, justified opt-out.

The ephemeral exception: heartbeat Heartbeat's base class sets jetstream=False in its own init. A heartbeat's meaning is its absence — a missed live beat is the signal something is dead. Durability would redeliver a dead agent's stale beats (the retention lies). And a heartbeat that did not arrive has nothing to recover — no retry, no DLQ. The base owns this so every client inherits it without knowing heartbeats are special.

Hard rules (stamped on every worker brief)

  1. fleet-core is the base; import it, do not reinvent. Capability gaps → file back as a fleet-core issue, never fork the transport or hand-format a subject.
  2. The spec is code: signals are typed Pydantic fields, never prose trailers. [[done]]/[[stance:]] are deleted at the root.
  3. Durable-by-default; the only ephemeral exception is heartbeat. Losing durability is an explicit, justified opt-out.
  4. extra="allow" for client-specific signal; the agreed fields validate hard.
  5. mypy --strict + ruff + pytest green; disjoint write sets per lane.
  6. Backward compat: re-pointing a package keeps its existing consumers working — no silent break across the fleet.
