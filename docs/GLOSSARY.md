# Glossary

Project-specific terminology for fleet-bus. All agents and contributors use
these definitions. The canonical cross-repo source is `_DOCS/GLOSSARY.md`; this
file is the fleet-bus-local view of the terms fleet-bus owns.

## Domain Terms

| Term | Definition | NOT This |
|------|-----------|----------|
| **envelope** | **Transport.** The wire frame the bus reads to route, dedupe, auth, decide durability, and deliver a message -- the known wire keys plus `typed_signal` (`fleet_core.spec.Envelope`). Its body is four fixed slots (`header · data · extras · footer`, `fleet_core.contract.Payload`), but the bus treats that body as opaque -- validated only to *be* a well-formed body, never inspected for meaning. fleet-bus owns the envelope; every NATS actor rides it. See `docs/contracts/C6-envelope-vs-message-body.md`. | The message contents or meaning; an actor's data format; the NATS subject (routing lives in the subject, not the envelope body). |
| **contract** | **What's in / the format of a message.** The shape a producer and consumer agree to exchange, carried *inside* the envelope's `data` slot -- e.g. Open Brain's `agent_context_pack` request/response, k-board's event body. Owned by the **actor**, never by fleet-bus: fleet-bus guarantees the envelope carries `data`, the actor defines what `data` means (strict or open is the actor's call). | The envelope/transport frame (fleet-bus's job); the four-slot `Payload` shape (that's the envelope body, which *carries* a contract); anything the bus inspects. |
| **lane** vs **subject template** | **Two different registry facts.** A *lane* is a name in the role->lanes map (`CODE_ROLE_LANES`, k-board `nats_role_lanes`) saying **a role SUBSCRIBES to it**. A *subject template* is an entry in the subject catalog (`CODE_SUBJECTS`, k-board `nats_subjects`) saying **the subject exists and how it is built**. A publish-only principal has a template but **no lane** -- it subscribes to nothing, so it registers nothing in the lane map. | Interchangeable terms. Registering a lane does not create a subject, and a subject with no lane is not "unregistered" -- it is simply not subscribed by any role. |
| **publish-only principal** | A bus identity that may PUBLISH on a narrow subject and must **never SUBSCRIBE to anything**. Declared client-side in `CODE_PUBLISH_ONLY_ROLES` (an invariant, not a boundary) and **enforced server-side** by `subscribe { deny = [">"] }` on its NATS credential. Existing seats: `fleet-hub-control`, `fleet-kboard`, `fleet-runner`. | A role with an empty lane list (that is unshippable -- the registry rejects it); a client-side setting that confines anything on its own. The server deny is the only real boundary. |
| **runner box** | A disposable privileged LXC clone that runs a coding agent with `bypassPermissions` / `sandbox_mode=danger-full-access` over **untrusted repository content**, executing software-factory jobs (rodaddy/rodaddy-watcher#70). It publishes progress on `{env}.factory.runner.{job_id}` and receives its work over the durable Postgres path, never over NATS. | A fleet agent (Skippy/Bilby/Nagatha); a bus subscriber; a trusted publisher. Its output is untrusted and must never reach an LLM turn. |
